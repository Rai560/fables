I. EDA 探索性数据分析

EDA = Exploratory Data Analysis。建模前先"翻一翻"数据:有几种类型?有没有缺失/异常值?怎么分布?变量间有没有相关?(看统计量、画直方图/散点图/箱线图)

ML 流程做什么大白话(做饭)
1. 收集数据把数据搞到手买菜
2. EDA 探索性分析看看数据长什么样检查食材新不新鲜
3. 数据预处理清洗、转换数据洗菜切菜
4. 训练模型让模型学习开火炒菜
5. 评估模型看模型好不好尝尝味道
6. 部署上线模型投入使用上桌开吃

J. ROC / AUC(二分类评估)

ROC = 一条曲线(展示模型在不同"松紧阈值"下的表现)。X 轴 = 假阳性率 FPR(好人被冤枉的比例),Y 轴 = 真阳性率 TPR(坏人被抓到的比例)。AUC = 曲线下面积,用一个数字总结模型好坏。口诀:ROC 是曲线,AUC 是数字,越接近 1 越牛。

AUC 值含义大白话
1.0完美模型每次都判断对,神仙
0.9 – 1.0非常好学霸级别
0.7 – 0.9还不错中等偏上
0.5跟瞎猜一样抛硬币
< 0.5比瞎猜还差反着来反而更准
💡 ROC/AUC 专门用于二分类问题(是/否、正/负、垃圾邮件/正常),是评估分类模型好坏的标准方法。

N. 生成式AI · 评估指标 · 算法 大辨析(7/31 刷题笔记)

① GAN(生成对抗网络):两个神经网络打架——生成器(Generator)造假样本,判别器(Discriminator)辨真假,互相博弈到生成器造得以假乱真。是一种生成式模型架构(和 Transformer、扩散模型 Diffusion 并列),常用来生成图像。

② Amazon SageMaker Canvas:无代码(no-code)可视化建模工具。业务分析师不用写代码,拖拽点选就能训练模型、做预测。关键词=零代码、给不懂编程的人用。

③ Amazon SageMaker DeepAR:内置算法,专做时间序列预测(基于 RNN)。喂历史时间序列 → 预测未来(需求/销量预测)。看到"时间序列 + SageMaker 内置算法"就想它。

评估指标大辨析(⚠考试最爱的陷阱:看任务类型选指标)

任务类型该用的指标
分类(Classification)混淆矩阵、准确率、精确率/召回率、F1 值、AUC/ROC
回归(预测连续数值)R² 分数、MSE(均方误差)、RMSE(均方根误差)、MAE
机器翻译BLEU(双语评估替补,偏精确率,比对译文与参考的 n-gram 重叠)
文本摘要ROUGE(偏召回率,看生成摘要覆盖了多少参考内容)
⚠ 相关矩阵(Correlation Matrix)这不是模型评估指标!是 EDA 阶段看变量间相关性用的

三句话记牢:
• 翻译用 BLEU(精确)、摘要用 ROUGE(召回)——都是文本生成指标。
• R²/MSE/RMSE 是回归的;F1 是分类的——别串门。
• 相关矩阵是"探索数据",不是"评估模型"。

算法辨析

算法类型 & 干什么
k-NN(K 近邻)监督学习,分类/回归——看最近的 K 个邻居"投票"
K-means(K 均值)⚠无监督,聚类。和 k-NN 名字像但完全不同(一个监督分类,一个无监督分组)
ARIMA(自回归积分滑动平均)经典时间序列预测模型(统计方法)
线性回归监督,回归(预测连续数值)
主题建模(如 LDA)无监督 NLP——从文本自动发现主题
聚类模型(Clustering)无监督——把相似数据分组
规范性 ML(Prescriptive)不只预测"会发生什么",还建议"该怎么做"(分析四层:描述→诊断→预测→规范,最高层)
基于 BERT 的模型BERT=预训练语言模型,擅长"理解"类 NLP(分类/问答/实体识别),encoder 型

模型评估 vs 对齐方法(⚠别混)

方法是什么
自动模型评估(Automatic)用指标或另一个模型自动打分——快、便宜、可规模化
人工评估(Human)人来判断质量,适合主观 / 安全性这类指标
众包评估(Crowdsourced)找一大批人来评(人工评估的规模化形式)
⚠ RLHF(从人类反馈中强化学习)这不是评估,是对齐训练方法——用人类偏好反馈微调模型,让它更符合人类期望(如 ChatGPT 的对齐)

陷阱:题目问"怎么评估模型"时,RLHF 常是干扰项(它是训练手段)。Bedrock/SageMaker 的模型评估分"自动"和"人工"两种。

正则化参数(Regularization)

正则化=防止过拟合的技术:给模型复杂度加"惩罚",逼它别死记训练数据里的噪声。

正则化参数(如 λ/lambda)=控制惩罚力度的超参数:

调整后果
参数调大模型更简单 → 可能欠拟合
参数调小模型更复杂 → 可能过拟合

常见两种:L1(Lasso)能把不重要特征的系数压到 0(=顺便做特征选择);L2(Ridge)把系数压小但不为 0。

1.1 核心概念(中英对照)

AI ⊃ ML ⊃ 深度学习:层层包含

AI 人工智能 · Artificial Intelligence
让机器模拟人类智能的大领域(连规则系统也算)
ML 机器学习 · Machine Learning
AI 的子集:从数据自动学规律,不靠人手写死规则
DL 深度学习 · Deep Learning
ML 的子集:用多层神经网络,擅长图像/语音/文本

一句话:所有深度学习都是机器学习,所有机器学习都是 AI;反过来不成立。

必背术语表

英文中文一句话理解
Neural Network神经网络模仿大脑神经元的多层结构,深度学习的基础
Model模型训练后得到的"成品",能对新数据做预测
Algorithm算法训练模型用的"方法/配方"(决策树、神经网络等)
Training训练用数据"喂"模型、让它学规律的过程
Inference推理用训练好的模型对新数据做预测(线上真正干活)
Computer Vision (CV)计算机视觉让机器"看懂"图像 / 视频
NLP自然语言处理让机器"读懂 / 生成"人类语言
LLM大语言模型超大规模、训练在海量文本上的模型
Bias偏差 / 偏见模型系统性偏向某类结果,可能造成不公平
Fairness公平性模型对不同人群一视同仁、不歧视
Overfitting过拟合模型死记训练集,遇到新数据就翻车(记太死)
Underfitting欠拟合模型太简单,连训练集都学不好(学太浅)
💡 过拟合 vs 欠拟合(高频):过拟合=训练集分高、测试集分低(记住了噪声);欠拟合=两边都低(没学到规律)。理想是 good fit,两边都好。

1.2 应用场景与技术选型

什么时候该用 / 不该用 AI

✅ 适合用 AI/ML

  • 要处理海量数据、规模化(scalability)
  • 规律复杂,难用固定规则写死
  • 要自动化重复决策
  • 能接受"预测"(概率性结果)

❌ 不适合用 AI/ML

  • 需要 100% 确定、精确的答案(不是预测)
  • 简单固定规则就能解决
  • 数据太少 / 质量太差
  • 成本 > 收益(不划算)
💡 考点:题目常给场景问"该不该用 ML"。记住反例:需要确定、可复现的精确结果(算税、财务对账)用传统程序,别用会"预测"的 ML。

三种技术怎么选(高频)

技术输出什么时候用例子
回归 Regression连续数值预测一个"数"房价、销量、气温
分类 Classification离散类别判断"属于哪一类"垃圾邮件、欺诈/正常、猫/狗
聚类 Clustering分组(无标签)没有标签,自动分群客户分群、相似商品归堆

1.3 ML 开发生命周期

一条完整的 ML 流水线(9 步)

#阶段做什么
1数据收集 Data Collection把训练要用的原始数据攒起来
2探索性分析 EDA先看看数据长啥样、有没有坑
3数据预处理 Pre-processing清洗、去重、补缺失、归一化
4特征工程 Feature Engineering把原始数据加工成模型好用的"特征"
5模型训练 Model Training用算法在数据上学出模型
6超参数调优 Hyperparameter Tuning调"旋钮"(学习率等)让模型更好
7评估 Evaluation用没见过的数据测模型好不好
8部署 Deployment上线,让模型对外提供预测
9监控 Monitoring盯线上表现,发现漂移就重训
MLOps(机器学习运维)= 把 DevOps 的自动化 / CI-CD / 监控 / 版本管理搬到 ML,让"训练→部署→监控→再训练"这条链自动、可重复地跑。

模型从哪来 & 怎么上线

话题选项
模型来源① 开源预训练模型(拿来即用 / 微调)   ② 自己从头训练自定义模型
上线方式① 托管 API 服务(AWS 帮你管)   ② 自建 API(自己维护服务器)

评估指标(必背)

指标含义直觉
准确率 Accuracy预测对的 / 全部整体对多少;类别不平衡时会骗人
精确率 Precision预测为正里真为正的比例"报警的里有多少是真的"(误报少)
召回率 Recall真实为正里被找出的比例"真坏人里抓到多少"(漏抓少)
F1 分数 F1 Score精确率与召回率的调和平均两者兼顾的综合分
AUC / ROCROC 曲线下面积整体区分能力,1 满分、0.5 瞎猜
混淆矩阵 Confusion MatrixTP/FP/TN/FN 四格表上面指标都从它算出来
💡 业务指标别忘:技术指标之外,考纲要你懂业务侧怎么衡量——ROI 投资回报、每用户成本、开发成本、客户反馈。题会问"该用哪个指标向业务方汇报价值"。
