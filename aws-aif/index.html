I. EDA 探索性数据分析

EDA = Exploratory Data Analysis。建模前先"翻一翻"数据:有几种类型?有没有缺失/异常值?怎么分布?变量间有没有相关?(看统计量、画直方图/散点图/箱线图)

ML 流程做什么大白话(做饭)
1. 收集数据把数据搞到手买菜
2. EDA 探索性分析看看数据长什么样检查食材新不新鲜
3. 数据预处理清洗、转换数据洗菜切菜
4. 训练模型让模型学习开火炒菜
5. 评估模型看模型好不好尝尝味道
6. 部署上线模型投入使用上桌开吃

J. ROC / AUC(二分类评估)

ROC = 一条曲线(展示模型在不同"松紧阈值"下的表现)。X 轴 = 假阳性率 FPR(好人被冤枉的比例),Y 轴 = 真阳性率 TPR(坏人被抓到的比例)。AUC = 曲线下面积,用一个数字总结模型好坏。口诀:ROC 是曲线,AUC 是数字,越接近 1 越牛。

AUC 值含义大白话
1.0完美模型每次都判断对,神仙
0.9 – 1.0非常好学霸级别
0.7 – 0.9还不错中等偏上
0.5跟瞎猜一样抛硬币
< 0.5比瞎猜还差反着来反而更准
💡 ROC/AUC 专门用于二分类问题(是/否、正/负、垃圾邮件/正常),是评估分类模型好坏的标准方法。

K. 混淆矩阵四件套 TP / FP / TN / FN

缩写全称意思比喻(抓小偷)

N. 生成式AI · 评估指标 · 算法 大辨析(7/31 刷题笔记)

① GAN(生成对抗网络):两个神经网络打架——生成器(Generator)造假样本,判别器(Discriminator)辨真假,互相博弈到生成器造得以假乱真。是一种生成式模型架构(和 Transformer、扩散模型 Diffusion 并列),常用来生成图像。

② Amazon SageMaker Canvas:无代码(no-code)可视化建模工具。业务分析师不用写代码,拖拽点选就能训练模型、做预测。关键词=零代码、给不懂编程的人用。

③ Amazon SageMaker DeepAR:内置算法,专做时间序列预测(基于 RNN)。喂历史时间序列 → 预测未来(需求/销量预测)。看到"时间序列 + SageMaker 内置算法"就想它。

评估指标大辨析(⚠考试最爱的陷阱:看任务类型选指标)

任务类型该用的指标
分类(Classification)混淆矩阵、准确率、精确率/召回率、F1 值、AUC/ROC
回归(预测连续数值)R² 分数、MSE(均方误差)、RMSE(均方根误差)、MAE
机器翻译BLEU(双语评估替补,偏精确率,比对译文与参考的 n-gram 重叠)
文本摘要ROUGE(偏召回率,看生成摘要覆盖了多少参考内容)
⚠ 相关矩阵(Correlation Matrix)这不是模型评估指标!是 EDA 阶段看变量间相关性用的

三句话记牢:
• 翻译用 BLEU(精确)、摘要用 ROUGE(召回)——都是文本生成指标。
• R²/MSE/RMSE 是回归的;F1 是分类的——别串门。
• 相关矩阵是"探索数据",不是"评估模型"。

算法辨析

算法类型 & 干什么
k-NN(K 近邻)监督学习,分类/回归——看最近的 K 个邻居"投票"
K-means(K 均值)⚠无监督,聚类。和 k-NN 名字像但完全不同(一个监督分类,一个无监督分组)
ARIMA(自回归积分滑动平均)经典时间序列预测模型(统计方法)
线性回归监督,回归(预测连续数值)
主题建模(如 LDA)无监督 NLP——从文本自动发现主题
聚类模型(Clustering)无监督——把相似数据分组
规范性 ML(Prescriptive)不只预测"会发生什么",还建议"该怎么做"(分析四层:描述→诊断→预测→规范,最高层)
基于 BERT 的模型BERT=预训练语言模型,擅长"理解"类 NLP(分类/问答/实体识别),encoder 型

模型评估 vs 对齐方法(⚠别混)

方法是什么
自动模型评估(Automatic)用指标或另一个模型自动打分——快、便宜、可规模化
人工评估(Human)人来判断质量,适合主观 / 安全性这类指标
众包评估(Crowdsourced)找一大批人来评(人工评估的规模化形式)
⚠ RLHF(从人类反馈中强化学习)这不是评估,是对齐训练方法——用人类偏好反馈微调模型,让它更符合人类期望(如 ChatGPT 的对齐)

陷阱:题目问"怎么评估模型"时,RLHF 常是干扰项(它是训练手段)。Bedrock/SageMaker 的模型评估分"自动"和"人工"两种。

正则化参数(Regularization)

正则化=防止过拟合的技术:给模型复杂度加"惩罚",逼它别死记训练数据里的噪声。

正则化参数(如 λ/lambda)=控制惩罚力度的超参数:

调整后果
参数调大模型更简单 → 可能欠拟合
参数调小模型更复杂 → 可能过拟合

常见两种:L1(Lasso)能把不重要特征的系数压到 0(=顺便做特征选择);L2(Ridge)把系数压小但不为 0。

1.2 应用场景与技术选型

什么时候该用 / 不该用 AI

✅ 适合用 AI/ML

  • 要处理海量数据、规模化(scalability)
  • 规律复杂,难用固定规则写死
  • 要自动化重复决策
  • 能接受"预测"(概率性结果)

❌ 不适合用 AI/ML

  • 需要 100% 确定、精确的答案(不是预测)
  • 简单固定规则就能解决
  • 数据太少 / 质量太差
  • 成本 > 收益(不划算)
💡 考点:题目常给场景问"该不该用 ML"。记住反例:需要确定、可复现的精确结果(算税、财务对账)用传统程序,别用会"预测"的 ML。

因素看什么

推理参数:怎么影响输出(高频送分)

参数作用调高会怎样
Temperature 温度控制随机性 / 创造性越高越发散有创意；越低越确定保守
Top-p(核采样)从累积概率前 p 的词里选越高候选词越多、越多样
Top-k从概率最高的 k 个词里选同理，k 越大越多样

💡 最常考:要结果稳定 / 少胡说 / 可复现 → 调低 temperature(甚至设 0)；要更有创意 / 多样 → 调高 temperature。

RAG 检索增强生成(D3 核心中的核心)

RAG = Retrieval Augmented Generation。让模型回答前，先去你的知识库检索相关资料，再带着这些真实资料生成答案。

解决什么:① 模型不知道你公司的私有 / 最新数据 → RAG 把它喂进去；② 减少幻觉(基于真实资料回答)；③ 比微调便宜、还能随时更新数据。

RAG 四步做什么
1. 分块 Chunking把文档切成小块
2. 嵌入 Embedding每块转成向量，存进向量数据库
3. 检索 Retrieval用户提问也转向量，找语义最相近的几块
4. 生成 Generation把检索到的资料 + 问题一起给模型，生成有依据的答案
💡 AWS 里做 RAG 的托管方案 = Amazon Bedrock Knowledge Bases(知识库)。看到“基于公司文档回答”“减少幻觉又不想训模型”→ 答 RAG / Knowledge Bases。

向量数据库:embedding 存哪

AWS 服务说明
Amazon OpenSearch Service最常见的向量检索选项
Aurora / RDS for PostgreSQL(pgvector)关系库加 pgvector 扩展
Amazon Neptune / DocumentDB / MemoryDB也提供向量能力

四种定制方式:成本从低到高(必考阶梯)

方式怎么做成本 / 何时用
① 提示工程只改提示词，不动模型最便宜，先试这个
② RAG把资料喂进上下文较便宜，要私有 / 最新知识时用
③ 微调用自己数据再训练较贵，要特定风格 / 领域时用
④ 预训练从零训 FM最贵，几乎没人做
⚠️ 决策顺序:先提示工程 → 不够就 RAG(缺知识) → 还不够再 微调(要风格 / 领域能力)。题问“最省成本”→提示工程；“用公司最新数据”→RAG；“学会特定语气”→微调。

Agents 代理:做多步任务

Agent = 让模型自己拆任务、调工具 / API、多步完成复杂事。AWS = Amazon Bedrock Agents。看到“多步骤 / 自动编排”→ Agents。

方式意思

2.1 核心概念(中英对照)

LLM大语言模型专门处理文本的基础模型(如 Claude、Titan、Llama)
Token词元 / 令牌模型处理文本的最小单位(约 = 一个词或词的一部分)。长度和计费都按 token 算
Embedding嵌入把文字 / 图片转成一串数字(向量),让机器能算“语义相似度”
Vector向量embedding 产出的那串数字;语义相近的内容,向量也相近
Chunking分块把长文档切成小块再做 embedding / 检索(RAG 常用)
Prompt提示词你给模型的输入指令
Prompt Engineering提示工程靠把提示词写好来引导模型输出更优结果(不改模型,最省成本的优化手段)
Transformer转换器架构现代 LLM 的底层网络架构,靠“注意力机制”理解上下文关系
Multi-modal多模态能同时处理多种模态的输入 / 输出(文字 + 图片 + 音频)
Diffusion Model扩散模型主流图像生成模型:从噪声一步步"去噪"出图(如 Stable Diffusion)
Context Window上下文窗口模型一次能“看”的最大 token 量(输入 + 输出的容量上限)
Temperature温度控制输出随机性 / 创造性的旋钮:高 = 更发散,低 = 更确定保守
💡 高频区分:Token = 切文本的单位、按它计费;Embedding / Vector = 把内容变数字好算相似度;Chunking = 把长文切小块。三个常一起出现在 RAG 场景题里。

Token 直觉:一句话是怎么被切的

拿 "Generative AI is amazing" 举例,模型不是按"整句"或"整词"处理,而是切成 token 再算:

Generative AI is amazing

粗算:英文里 1 个 token ≈ 0.75 个单词;中文一个字往往就是 1~2 个 token。输入越长、输出越长,token 越多,花的钱越多——这是 Bedrock 按量计费的基础。

生成式 AI 能做什么(应用场景)

文本生成 / 写作摘要总结翻译代码生成聊天机器人客服助手图像生成视频生成音频 / 配音智能搜索个性化推荐

💡 反例(别选生成式AI):要精确、可复现、确定的结果(算账、对数、结构化预测)还是用传统程序 / 判别式 ML;生成式AI会"编"(见下方幻觉),不适合要求 100% 准确的场景。

基础模型生命周期(7 步)

#阶段做什么
1数据选择 Data Selection挑用来预训练 / 适配的数据
2模型选择 Model Selection选合适的基础模型架构 / 现成 FM
3预训练 Pre-training在海量通用数据上从头训练出通用能力(极贵、极耗算力)
4微调 Fine-tuning用少量领域数据再训练,让模型更懂你的场景 / 语气
5评估 Evaluation测模型表现(准确性、相关性、安全性等)
6部署 Deployment上线对外提供服务
7反馈 Feedback收集使用反馈(含 RLHF 人类反馈)持续改进
预训练 vs 微调(高频):预训练 = 从零学通用能力(贵、慢、通常用现成的);微调 = 在现成 FM 上用自己的小数据再教一遍(便宜得多,让它更贴你的业务)。

2.2 能力与局限

生成式 AI 的三大优势

优势意思
适应性 Adaptability一个 FM 能干很多任务(写作 / 翻译 / 问答 / 代码),不用为每个任务单独训模型
响应快 Responsiveness能快速生成内容,近乎实时
简单 Simplicity用自然语言就能用,大幅降低使用门槛(不用懂机器学习)

生成式 AI 的四大局限(必考)

局限意思怎么应对
幻觉 Hallucination一本正经编造看似合理、实则错误的内容RAG 接真实数据、人工复核、加 Guardrails
可解释性差 Interpretability难说清它为什么给这个答案(黑盒)关键决策别全交给它、留人复核
不准确 Inaccuracy可能输出事实错误核对事实、限定知识来源
非确定性 Nondeterminism同样输入可能得到不同输出(有随机性,受 temperature 影响)需稳定就调低 temperature
⚠️ 幻觉是 D2 头号考点。看到"模型给了错的 / 编的信息""如何减少不实回答"→ 答案方向基本都指向 RAG(检索增强,让它基于真实数据回答) + 人工复核 + Guardrails 护栏。

选哪个模型?看这几点

因素考虑什么
模型类型 Model Type要文本 / 图像 / 多模态?任务对不对口
性能要求 Performance准确度、延迟(响应速度)要多高
能力 Capabilities上下文窗口多大、支持哪些语言 / 模态
约束 Constraints成本预算、延迟上限、能否微调
合规 Compliance数据隐私、行业监管、模型许可

业务价值怎么衡量(业务指标)

指标看什么
跨领域表现 Cross-domain performance一个模型在多类任务上通用得好不好
效率 Efficiency省了多少人力 / 时间 / 成本
转化率 Conversion Rate带来多少成交 / 完成率提升
每用户平均收入 ARPUAverage Revenue Per User
准确率 Accuracy输出对不对
客户终身价值 CLVCustomer Lifetime Value,长期价值
💡 技术指标(准确率)之外,考纲要你懂业务侧怎么算账——效率提升、转化率、ARPU、CLV。题会问"该拿哪个指标向业务方证明生成式AI的价值"。

🗺️ AWS 生成式 AI 服务速记表(考试重点)

D2 / D3 的送分点:看场景秒配服务。Bedrock 是绝对核心,务必记牢它的定位。
服务干什么一句话记忆
Amazon Bedrock全托管服务,一个 API 访问多家基础模型(Anthropic Claude、Amazon Titan / Nova、Meta Llama、Mistral、Stability AI 等),用来构建生成式AI应用;内置微调、Knowledge Bases(RAG)、Agents、Guardrails建生成式AI应用就找它(D2/D3 头号主角)
Amazon SageMaker JumpStartML 模型中心,提供预训练模型(含 FM)+ 一键部署 / 微调要更多控制 / 自己微调 FM → JumpStart(面向 ML 从业者)
PartyRock基于 Bedrock 的零代码生成式AI应用搭建"游乐场"不写代码、动手学着玩生成式AI(学习 / 实验用)
Amazon Q Business企业级生成式AI助手,连企业内部数据回答问题、做总结公司内部的"AI 员工助手"
Amazon Q Developer面向开发者的 AI 助手(原 CodeWhisperer),写代码 / 答 AWS 问题程序员的"AI 结对编程"
💡 易混:Bedrock = 建应用(调 API、可微调 / 加 RAG);PartyRock = 零代码玩;JumpStart = ML 从业者要更多控制、部署 / 微调模型;Amazon Q = 直接能用的成品助手(Business 对企业、Developer 对码农)。

用 AWS 建生成式 AI 的好处

好处意思
降低门槛 Lower barrier to entry不用自建 GPU 集群、不用从头训模型,开箱即用
高效 / 快速上市 Efficiency & Speed to market用现成 FM,几天就能出应用
成本可控 Cost-effectiveness按用量付费,不用前期重投入
安全合规 Security & Compliance数据留在你的 AWS 环境,不会拿你的数据去训别人的模型;满足行业合规
负责任 / 安全 Responsibility & SafetyGuardrails 等能力帮你过滤有害内容、控风险

成本怎么算(成本权衡)

方式 / 因素说明
按 token 计费 Token-based按输入 + 输出的 token 数付费,用多少付多少(适合流量不定 / 起步)
预置吞吐 Provisioned Throughput为高负载 / 稳定延迟预留容量,按时段买断(适合生产、大流量)
自定义模型 Custom Models微调 / 自定义会有额外训练 + 存储成本
其他权衡响应速度 responsiveness、可用性 availability、冗余 redundancy、性能 performance、区域覆盖 regional coverage
💡 省成本三招(高频):① 优先提示工程(不花训练钱);② 需要领域知识优先 RAG 而非微调;③ 流量小用按 token 付,流量大且稳再上预置吞吐。
